# formal_run_001 README 重构设计

日期：2026-10-10

## 目标

将 `formal_run_001` 中当前使用的六份 README 重构为面向审稿人和实验室成员的复现指南。README 只承担项目导航和运行说明，不再承载审计记录、核验结论、结果数值或科学结论。

## 修改范围

修改以下文件：

1. `README.md`
2. `formal_osla/README.md`
3. `outputs/output_formal/README.md`
4. `analysis/behaviour_analysis/README.md`
5. `analysis/fitting_NN/README.md`
6. `analysis/counterfactoral_lr/README.md`

不修改 `_archive/` 和 `_pre_change_backup_20261010/` 中的历史 README，也不修改任何模型、训练、测试、分析代码或正式结果文件。

## 信息架构

### 顶层 README

顶层 README 是整个复现流程的唯一入口，依次包含：

1. 项目用途与复现范围；
2. 目录结构；
3. Python 与 R/CmdStan 环境；
4. 快速健康检查；
5. 正式训练与冻结测试；
6. 行为分析、认知模型拟合和反事实分析的执行顺序；
7. 输入输出位置；
8. 防止覆盖正式产物的运行提示。

### 子目录 README

每份子 README 使用统一顺序：

1. 模块用途；
2. 目录或关键文件；
3. 输入；
4. 环境依赖；
5. 从明确工作目录执行的命令；
6. 输出；
7. 必要的运行注意事项。

子 README 不重复整套项目背景；跨模块内容链接到顶层 README 或相邻模块 README。

## 内容保留规则

保留复现实验所必需的信息：正式 seed、训练更新数、episode 数、协议名称、输入输出路径、执行顺序、命令参数、软件依赖、可能覆盖文件的行为，以及解释输出字段所必需的最小方法定义。

删除以下内容：

- 审计日期、审计过程和修复历史；
- “已验证”“核验通过”“逐字节一致”等结论；
- 当前运行得到的统计数值、收敛结论和模型优劣结论；
- 文件哈希比较和移植完整性评价；
- 研究结果解释、机制性结论和投稿措辞建议。

## 命令与路径规范

- 所有命令明确其工作目录。
- 顶层命令默认使用 `formal_run_001/.venv`，并注明可选的原项目虚拟环境。
- 主工作流只引用 `formal_run_001` 内部路径。
- 重算命令与只读检查命令分开列出。
- 对会覆盖或重写文件的命令给出简短提示。
- 不声称无法由当前环境完整验证的 R/Stan 重拟合已经运行成功。

## 验收标准

- 六份当前 README 都能独立回答“该目录是什么、需要什么输入、运行什么命令、产生什么输出”。
- README 中不再出现本次审计的结果或结论。
- 命令中的模块名、脚本路径和主要参数与现有代码一致。
- 归档与备份 README 保持不变。
- README 修改不触碰正式训练、测试、拟合或分析产物。
